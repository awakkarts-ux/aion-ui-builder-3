# Сборщик интерфейса Aion

Настольная программа для клиента Aion Classic: двигает панели интерфейса,
разблокирует их, меняет размер 3D-портрета, подменяет шрифт и иконки умений —
и сама пересобирает игровые `.pak`. Все правки обратимы одной кнопкой.

Electron + Node, внешних зависимостей кроме Electron нет.

```bash
npm install
npm start
```

Ярлык на рабочий стол:

```bash
powershell -ExecutionPolicy Bypass -File tools\make-shortcut.ps1 -Name "Сборщик интерфейса Aion"
```

## Что умеет

| Раздел | Что делает |
|---|---|
| Клиент | выбор папки `classic`, список подменённых файлов, профиль правок в файл и обратно |
| Раскладка HUD | поле 1280×960 поверх настоящего скриншота игры: тащишь мини-карту, панели умений, бафы, чат; снимаешь замок `not_movable`; прячешь и двигаешь отдельные элементы внутри диалога |
| Крупный портрет | размер окна портрета плюс согласованная позиция камеры, семь пресетов |
| Шрифт | подменяет три гарнитуры интерфейса своим `.ttf`, азиатскую не трогает |
| Иконки умений | 4037 иконок из `skills.pak`, подмена картинкой 64×64 |
| Цифры урона | цифры 0–9 в восьми цветах, знаки и таблички «Крит!», «Блок!», «Уворот!», «Парировано!», «Отражено!» |
| Картинки интерфейса | 193 атласа и картинки из `textures/ui`: рамки, кнопки, ячейки, полосы; выгрузка в PNG на правку |
| Вид Aion 5.x | переносит внешность 938 деталей из библиотеки `version5`, с показом «до и после» |
| Вид официального Classic | переносит внешность из другого клиента — официального Aion Classic 4Game: новый плоский вид `v3_*` и перерисованные детали, только то, что на экране реально изменится |
| Скины элементов | 3215 деталей из библиотек скинов: для каждой видно атлас, прямоугольник и вырезанный кусок; можно перенаправить на другой атлас, в том числе `v5_*` |
| Сборка | записывает паки, журнал, возврат к оригиналу |

## Как устроен клиент

Всё держится на двух разобранных форматах. Подробности — в комментариях
`src/core/pak.js` и `src/core/bxml.js`, здесь коротко.

**`.pak`** — это ZIP с побитово инвертированными сигнатурами, у каждой записи
зашифрованы только первые 32 байта. Шифр — XOR с куском статической таблицы из
`bin64/crysystem.dll`, и кусок выбирается не абы как:

```
keyOffset = tableBase + (compressedSize mod 1024)
```

Правило сошлось на всех 29 600 записях клиента, так что перебор нужен один раз
— найти `tableBase` в конкретной сборке. Писать можно и обычным ZIP (клиент
такой читает), но штатные паки мы заменяем в родном формате.

**Бинарный XML** в `data/ui/*.pak` — таблица строк в UTF-16 плюс дерево узлов,
где имена и значения заданы смещениями в эту таблицу:

```
0x80 | varint длина таблицы | таблица строк | дерево
узел: имя, флаги, [текст], [число атрибутов + пары], [число детей + узлы]
флаги: 1 — есть текст, 2 — есть атрибуты, 4 — есть дети
```

Все 256 бинарных XML клиента разбираются и собираются обратно **байт в байт** —
это проверяет `npm run selftest`.

Геометрия интерфейса лежит в атрибутах `frame="x,y,ш,в"` и `flag="..."`
диалогов. Координаты — в виртуальном экране 1280×960, клиент сам растягивает
его под разрешение, опираясь на `h_pos_align` / `v_pos_align`.

## Где на самом деле лежит интерфейс

Грабли, на которые легко наступить: те же диалоги лежат **дважды** —
в `data/ui/*.pak` и в `l10n/<язык>/data/data.pak` под префиксом `UI/`.
Клиент читает **локализованную копию**, правки в `data/ui` он игнорирует.
Проверено на живом клиенте: после записи только в `data/ui` интерфейс не
сдвинулся, а копия в `l10n` осталась со штатными координатами.

Из 275 записей `UI/` в локализованном паке 232 байт в байт совпадают с
`data/ui`, различаются только html-описания классов и `CreateInfos`; 9 файлов
есть лишь в `data/ui` (среди них `UI_ModelCam.xml` — камера портрета), 11
только в `l10n`. То есть перекрытие пофайловое: правим обе копии, каждую там,
где она есть.

`data.pak` весит 119 МБ и содержит 22 тысячи записей, поэтому целиком он не
пересобирается: `pak.patchPak` подменяет только нужные записи, остальные
копирует байтами вместе с их шифрованием. Полный цикл правок укладывается в
полторы секунды.

То же самое с картинками. Иконки умений лежат в одном месте
(`data/skills/skills.pak`), а вот цифры урона — в двух:

- цифры 0–9, плюс и минус — `textures/ui/hit_number/hit_number.pak`, 32×32;
- таблички `critical`, `block`, `dodge`, `parry`, `resist` — там же лежат
  корейские 194×70, **но игра показывает переведённые** из
  `l10n/<язык>/textures/textures.pak` (`UI/hit_number/…`, 248×76 и 268×76,
  сжатие DXT5, у `Resist_R/W` ещё и другой регистр в имени).

Хуже того, `v4_common.dds` лежит **в трёх паках сразу**: `textures/ui/ui.pak`,
локализованный `textures.pak` и пользовательский пак-перебивалка
(`zz_*.pak`). Кто из них выигрывает — зависит от порядка монтирования, и
надёжно мы этого не знаем.

Поэтому копии **не схлопываются**: каждая показана своей ячейкой с подписью
пака, ключ правки — `пак|запись`. Можно заменить любую копию или все сразу,
вместо того чтобы угадывать приоритет и промахнуться.

## Две версии интерфейса в одном клиенте

`data/ui/preload/preload.pak` держит две полные библиотеки скинов:
`version4.xml` (1068 скинов, атласы `v4_*`) — её Classic и использует — и
`version5.xml` (2665 скинов, атласы `v5_*`) — интерфейс Aion 5.x. Картинки для
обеих лежат в `textures/ui`.

Переключить одну на другую нельзя: имена скинов почти не пересекаются (общих
36), а диалоги Classic просят именно `v4_*` — подмена библиотеки оставила бы
интерфейс без графики.

Но имена устроены единообразно: `v4_button_up` ↔ `v5_button_up`. Поэтому
раздел «Вид Aion 5.x» не подменяет библиотеку, а переписывает каждой записи v4
её внешность — атлас, прямоугольники, размеры кусков — беря их у одноимённой
записи v5. Имя остаётся прежним, значит диалоги и пресеты продолжают её
находить, а умения и их названия вообще не затрагиваются.

Пары ищутся четырьмя правилами, каждое включается отдельно и показывает, что
именно добавило:

| Правило | Даёт | Пример |
|---|---|---|
| по имени | +938 | `v4_button_up` → `v5_button_up` |
| с точностью до подчёркиваний | +6 | `v4_tab_button_up` → `v5_tabbutton_up` |
| подставить обычное состояние | +3 | `v4_mailicon` → `v5_mailicon_up` |
| свести варианты к одному | +14 | `v4_dialog3` → `v5_dialog` |

Последнее по умолчанию выключено: оно схлопывает разные варианты рамок в один,
и это уже вопрос вкуса, а не механики. С настройками по умолчанию переносится
**947** деталей.

Три записи пропускаются всегда — ссылаются на отсутствующий в клиенте атлас
`tournament_3`. Оставшиеся 118 (внутриигровой магазин, почта, инвентарь,
экипировка) в пятой версии названы иначе, пары им нет — они остаются в старом
виде. Поэтому «по максимуму», а не «целиком».

Отдельные детали можно доправить вручную в разделе «Скины элементов»; такие
правки применяются поверх массового переноса. Всё ложится в `preload.pak` и в
его копию внутри локализованного пака.

Отдельно: **два набора HUD переключаются штатно**, без всяких правок —
Настройки → «Вид HUD». Это `game_hud_s1` и `game_hud_s2`, разные раскладки и
разные пресеты (`v4_hud_char_s1` против `s2`, крупный 3D-портрет против герба).

## Вид официального Classic

Раздел берёт внешность из **другого** клиента — официального Aion Classic
(4Game). Он только читается: ключ его паков находится сам (формула та же,
база таблицы в `CrySystem.dll` другая — `0x200430`).

Новый плоский вид официальный клиент рисует библиотекой `version3` (и ещё
`ver4`, `ver5`): скины `v3_*` на атласах `v3_common_*`, `main_menu_01`. Зовут их
только его собственные окна, наши просят `v4_*`. Поэтому схема та же, что у
вида 5.x: имя остаётся, внешность берётся у пары. Источников три:

| Источник | По умолчанию | Даёт | Пример |
|---|---|---|---|
| новый вид Classic | вкл | 162 | `v4_quickbar_slot_bg` → `v3_quickbar_slot_bg` |
| перерисованное у официального | вкл | 278 | та же деталь в той же библиотеке, другая картинка |
| новый вид — детали другой формы | выкл | 48 | `v4_gauge_red_sm` 123×6 → `v3_gauge_red_sm` 88×8 |

«Другой формы» — простая картинка, у которой пропорции разошлись больше чем на
15% или размер больше чем в полтора раза, либо рамка против картинки. Окно
задаёт размер жёстко, такая картинка растянется или обрежется — включать,
посмотрев «до и после».

**Считается только то, что на экране изменится.** Атласы `v4_common`,
`v4_popup1` у официального клиента отличаются по CRC, но основные куски в них те
же. Без сверки пикселей план обещал 1332 изменения, из которых видно было 278.
Теперь каждая пара сверяется попиксельно (с допуском на шум DXT), и совпавшие
не трогаются.

**Атласы донора с нашими не смешиваются.** Часть из них перерисована под теми
же именами и с другими координатами — подложить такой вместо своего значило бы
развалить остальные окна. Нужные атласы кладутся рядом под именами `cl_*` в
отдельный пак `textures/ui/zz_classic_look.pak`, и на них переводятся только
перенесённые детали. Атлас, одинаковый у обоих клиентов, не копируется. Пак
собирается заново при каждой сборке; выключил вид — он убирается, «Вернуть как
было» и сброс — тоже.

### Окна HUD

Панель умений, полосы HP/MP, опыт и радар так не меняются: в наборе s1 у
официального клиента они **байт в байт как у нас**, а новый HUD живёт в его
наборе **s2** — другие раскладки окон (панель умений 541×140, опыт во всю ширину)
на скинах с новыми именами. Поэтому окна s2 переносятся целиком
(`src/core/hudport.js`), но не как есть — код игры ищет виджеты по имени, а у
нас он старее официального:

- виджет, который наш код знает (имя есть в нашем окне), остаётся;
- оформление без поведения (фон, рамка, линия) остаётся;
- остальное убирается: в карточке группы у официального поверх MP лежат полосы
  `sp`/`ep`/`death`, которые прячет и показывает его код — у нас они висели бы
  мёртвыми полными полосами;
- наши виджеты, которых у официального нет, возвращаются — на место аналога
  (`emblem` вместо его 3D-портрета, `fly_gauge` вместо `fly_gauge01`).

Недостающие скины и пресеты (79 и 28) дописываются в `version4.xml` категорией
`classic_hud`, их атласы — в тот же `zz_classic_look.pak`. Переносятся панель
умений, опыт, HP/MP, питомец (набор s2) и цель, группа (общие для обоих наборов).
Цель и группа ставятся туда же, где стояли наши, с тем же замком — они общие
для обоих наборов. Мини-карта не подменяется, а перекрашивается: окно остаётся
нашим (у официального круг карты — другой тип виджета, наш код его не нарисует),
от официального берётся рамка, круг растягивается до его размера, кнопки
раскладываются вокруг. Меню не переносится: у официального из него вынесены
почта, магазин, пропуск и полоска полёта в окна, которых наш клиент не знает. В игре: «Вид HUD» → s2,
потом «Расположить окна по умолчанию».

Слои: вид 5.x → вид официального Classic → ручные правки «Скинов элементов».
Каждый следующий перекрывает предыдущий. Группы можно выключать по одной —
удобно проверять в игре по частям.

## Окна HUD расставляет код, а не XML

Координаты x/y окон HUD игра не слушает — только их размеры. Проверено на
установленном клиенте: сдвиг содержимого цели и новое место панели умений в
файлах — на экране без изменений. Правила набора s2, снятые со скриншотов:
цель пристёгнута к правому краю окна HP/MP; панель умений и меню — одна группа
по центру низа; полоса опыта начинается с «середина экрана − половина
панели». Поэтому перенос окон HUD двигает их размерами: панель умений шириной
в экран с рядом ячеек по центру, меню наполовину за правым краем, окно HP/MP
шире — и цель встаёт по центру. Размер экрана берётся из `system.cfg`.

## Сохранённая раскладка окон сильнее файлов

Клиент помнит, куда игрок сам растащил окна, и это перекрывает `frame` из XML.
После установки правок раскладки нужно один раз зайти в игре в **Настройки** и
нажать внизу **«Расположить окна по умолчанию»** (`reset_frame` в
`global_option_dialog.xml`). Размеры виджетов внутри диалога — например, окно
3D-портрета — так не перекрываются и применяются сразу.

## Игра должна быть закрыта

Пока клиент запущен, Windows держит паки занятыми. Раньше это ломалось
неприятно: запись падала с `EBUSY` на середине списка, часть паков успевала
обновиться, часть нет. Теперь сборка проверяет занятость всех файлов разом до
первой правки и просто говорит «Игра запущена — закрой клиент и повтори».

## Сброс к штатному виду

Кнопка на вкладке «Клиент» (или `node tools/reset-client.js --apply`) делает две
разные вещи:

- паки, которые правил сборщик, возвращает из резервных копий;
- файлы, которых в чистом клиенте не было вовсе — подменённые шрифты
  (`l10n/<язык>/data/Fonts/fonts.pak`) и сторонние паки поверх интерфейса
  (всё в `textures/ui`, кроме `ui.pak`) — убирает.

Убранное не удаляется, а переезжает в `%APPDATA%/aion-ui-builder/removed`.
Вернуть: кнопка «Вернуть убранное» или `node tools/reset-client.js --undo`.

## Резервные копии

Перед первой записью каждого штатного пака его копия уходит в
`%APPDATA%/aion-ui-builder/backup`. Исходником для правок всегда служит копия,
а не то, что сейчас в игре, — поэтому повторное применение профиля не
накладывается само на себя. «Вернуть как было» кладёт копии обратно и удаляет
наши файлы (шрифт, иконки).

Игра читает паки только при запуске: после сборки клиент надо перезапустить.

## Проверки

```bash
npm run selftest          # разбор и пересборка всех паков и XML клиента
node tools/roundtrip.js   # полный цикл правок на копии клиента, игру не трогает
node tools/roundtrip-classic.js ["E:\Aion Classic"]   # то же для вида официального Classic
node tools/selftest.js "E:\Aion Classic"               # самопроверка любого клиента
node tools/extract-client.js "E:\Aion Classic" <куда>  # выгрузить атласы, скины, XML в PNG/текст
node tools/serve.js 5174  # окно в браузере на выдуманных данных, без Electron
node tools/make-icon.js   # перерисовать icon.png и icon.ico
```

Снимок окна для проверки внешнего вида:

```bash
npx electron . --shot=out.png --view=layout
npx electron . --shot=out.png --view=classic --wait=9000 --scroll=#cl-samples
```

## Чего пока нет

- прозрачные пустые ячейки и снятие декоративных рамок — это правка атласов
  `v4_*.dds`, а не XML; скрипты для атласов лежат в соседнем `macrokit/tools`
- курсоры, настройки CFG, урон и эффекты из чужих сборщиков
- серые двойники подменённых иконок (`*_gray.dds`) не пересчитываются
