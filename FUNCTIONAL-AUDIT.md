# Функциональный аудит Aion UI Builder

Дата аудита: 6 ноября 2026 года

Проверяемая версия: `G:\Github code\aion-ui-builder 3`

## Что делает приложение

Приложение хранит профиль изменений интерфейса Aion Classic и применяет его к копиям паков клиента. Перед первой записью штатные файлы попадают в резерв. При повторной сборке исходником считается резервная копия, поэтому изменения не накапливаются поверх уже изменённого клиента.

Основная цепочка выглядит так:

1. `Client` проверяет папку `classic`, DLL клиента и наличие основных паков.
2. Профиль загружается из `userData`, проходит миграцию старых форматов и редактируется через UI.
3. `buildworker.js` запускает `build.apply()` в отдельном потоке.
4. `build.js` строит план изменений для XML, DDS, шрифтов, карт, скинов, HUD и паков.
5. `pak.js` делает точечные изменения записей через `patchPak`, сохраняя остальные записи пака.
6. Изменения в локализованных паках пишутся отдельно через `l10nWriteAll`.
7. `build:restore` возвращает файлы из резерва, а `reset.js` дополнительно убирает созданные программой файлы в карантин.

## Проверки, которые прошли

- `npm run selftest`
- `node tools/ui-selftest.js`
- `node tools/roundtrip.js`
- `node tools/security-selftest.js`
- `node tools/roundtrip-editor.js`
- `node tools/roundtrip-classic.js`
- `node tools/roundtrip-skillicons.js`

`roundtrip-editor.js` подтвердил замену элемента, собственную картинку, разделение общего скина, запись в `data/ui` и возврат паков байт-в-байт.

`roundtrip-classic.js` подтвердил перенос официального Classic с донором, HUD, скинов, атласов, карт, локализованных копий, порядок окон, раскладку s1/s2 и полный возврат.

После первой версии отчёта добавлены автоматический rollback снимка живых файлов при ошибке сборки и атомарная запись JSON-конфигурации через временный файл. Оба изменения проходят базовый `npm run check`, а редактор и иконки умений повторно прошли roundtrip.

## Найденные риски

### P1. Сборка не транзакционная — исправлено

`build.apply()` записывает группы изменений последовательно. Ранее при остановке после записи нескольких паков автоматического отката уже записанных паков не было. Теперь перед записью создаётся снимок живых файлов, а при исключении он восстанавливается. Резерв пользователя по-прежнему отвечает за возврат к исходному клиенту.

Снимок включает основные паки, локализации и паки карт. Его можно развить до более узкого журнала записанных путей, если стоимость копирования станет заметной на больших клиентах.

### P1. Профиль сохраняется после записи клиента

`main.js` сначала ждёт завершения сборки, затем отдельно пишет `profile.json`. Теперь JSON пишется атомарно через временный файл, поэтому обрезанный профиль не останется. Семантическая рассинхронизация всё ещё возможна, если клиент уже изменён, а запись профиля окончательно не удалась.

Следующее улучшение — хранить идентификатор последней успешно применённой сборки и показывать состояние рассинхронизации в UI.

### P1. Документация отставала от рабочей папки — исправлено

`HANDOFF.md` папки 3 обновлён и теперь указывает канонический путь `G:\Github code\aion-ui-builder 3`. Исторический handoff в старой папке сохранён как архивный источник.

### P2. Часть функций подтверждена только тестами паков

Roundtrip доказывает корректность записи и отката файлов, но не доказывает поведение реального клиента после запуска игры. Это касается предметных иконок, карт пользователя, замен редактора, скрабберов и части Electron-анимаций.

### P2. Главный процесс перегружен IPC-обработчиками

`src/main.js` содержит обработчики клиента, профиля, пресетов, сборки, Classic, карт, редактора, иконок и шрифтов. Это усложняет контроль жизненного цикла кэшей и обработку ошибок.

### P2. `executeJavaScript` используется для команд из аргументов запуска

Навигация и поиск из `main.js` передаются в renderer через `webContents.executeJavaScript`. Сейчас значения экранируются частично и сценарий локальный, но это хрупкий канал. Надёжнее сделать отдельный IPC-командный API для открытия раздела, поиска и прокрутки.

### P2. Профиль импортируется как объект без схемы

`profile:save` проверяет только размер и тип верхнего объекта. Глубокие поля не проходят единую схему. Часть профиля содержит пути к файлам и папкам, поэтому импортированный профиль стоит валидировать перед передачей в `build.apply()`.

### P3. Резервные имена используют плоскую замену разделителей

`Client.backupPath()` заменяет разделители на `__`. Пути с двойным подчёркиванием теоретически могут столкнуться при восстановлении. Для текущих путей Aion риск низкий, но формат лучше сделать структурированным или хранить manifest.

## Итог

Функциональное ядро подтверждено лучше интерфейсного слоя. Работа с резервами, PAK, XML, Classic-донором и редактором уже имеет сильное покрытие сквозными проверками. Основные оставшиеся задачи по надёжности связаны с семантической синхронизацией профиля и актуализацией документации.

Следующий технический приоритет — добавить rollback для частично записанной сборки, затем разделить IPC в `main.js` по доменам и обновить handoff под папку 3.
