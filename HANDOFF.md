### Как работает игра и что обсуждали (важно для редизайна)
- **Атлас = только пиксели.** Скин (`version4.xml`) говорит, какой кусок атласа брать. Окно (XML) задаёт виджеты и их имена. Поведение (заполнение полосы по HP, показ и скрытие, расстановка окон) в коде игры. Код находит виджеты по имени, виджет с неизвестным именем мёртвый.
- **Перенос между версиями возможен и уже работает:** донор (официальный Classic) → `donorimport.js` забирает библиотеки скинов, окна, атласы в `userData/official-classic/` в клиентских путях; `donor.js` переносит внешность по имени скина (`v4_x` ← `v3_x`); атласы донора кладутся как `cl_*` в `zz_classic_look.pak`; окна HUD переносит `hudport.js` с адаптацией под виджеты нашего кода (выкидывает `sp/ep/death`, возвращает `emblem`, `fly_gauge`). Моя ошибка в разговоре: я сказал, что два варианта HUD нельзя поменять местами. Пользователь поправил: можно, это и делает программа.
- Позиции окон HUD (x/y) игра не берёт, размеры берёт (см. раздел «Что НЕ сработало» ниже).
- **Открытый вопрос:** как заполняется полоса HP (скорее всего, подложка целиком и заливка, обрезанная по проценту). Если так, косые края надо рисовать и в подложке, и в заливке. Проверять опытом на одной полосе.
- Скрипт `tools/extract-client.js` идёт только в сторону клиент → Figma (атласы PNG, каждый скин отдельно, `skins.csv`, XML). **Обратного скрипта (рисунок → нарезка → атлас → пак) нет.** Кирпичики есть: `skins.js`, запись DDS, `patchPak`, `zz_builder.pak`.

### Что не сработало
- **Выпуск версии:** `electron-builder --publish always` из Actions создаёт **два** релиза с одним тегом (гонка параллельной загрузки, если релиза ещё нет): в одном `.exe` и `latest.yml`, в другом `.blockmap`. Так вышло с 0.1.8, я слил вручную через API. Выпускать так: сначала `gh release create vX.Y.Z --target main` (создаёт тег и релиз, запускает Actions), потом убедиться, что в релизе три файла: `.exe`, `.exe.blockmap`, `latest.yml`.
- Токен `gh` без права `workflow`: `.github/workflows/*` с сервера запушить нельзя (удалённо отклоняется). Такие файлы пользователь добавляет через сайт GitHub. Расширять права токена Claude не может; `gh auth refresh` классификатор запретил.
- Локальная сборка установщика на сервере невозможна: `electron-builder` требует `wine`, прав на установку нет. Собирать только через GitHub Actions.
- На сервере нет клиента игры: `selftest`, все `roundtrip-*` запускать нельзя. Для проверки реального поведения нужны данные от пользователя.
- В браузерной версии (mock) пустые сетка иконок умений, предпросмотр «Интерфейса» («редактор работает только в программе») и карточка зоны в «Картах», их проверить можно только в Electron.
- Первая попытка запустить чужой код (serve.js) классификатор отклонил; после явной просьбы пользователя всё работает.
- Версию 0.1.7 у пользователя исправить удалённо нельзя.

### Форматы (основа)
- Ключ пака: `keyOffset = tableBase + (compressedSize mod 1024)`, `tableBase` 0x21CCD0 (AionEmpire) / 0x200430 (4Game) в `bin64/crysystem.dll`
- Бинарный XML: все 256 XML пересобираются байт в байт (`npm run selftest`). DDS: чтение A8R8G8B8/DXT1/3/5, запись A8R8G8B8
- Интерфейс клиент читает из `l10n/<язык>/data/data.pak` (`UI/…`), `data/ui/*.pak` — вторая копия; пишем в обе
- Свои картинки программы — `textures/ui/zz_builder.pak` (квадратная карта, разметка, `bld_el_*`, **`bld_grip`**); атласы Classic — `zz_classic_look.pak`
- Строки: `Strings/client_strings_*.xml` (UTF-16, `<name>STR_…</name><body>…</body>`). Названия зон — `STR_ZONE_NAME_<КОД>`
- Шрифты игры: `l10n/rus/data/data.pak` → `Fonts/fontshader.xml` (шейдер → гарнитура, `logical_size`, цвет; rus: Calibri / Myriad Pro 12 px) + `Fonts/CALIBRI.TTF`, `MYRIADPR.TTF`

### Окна HUD мышью в игре (03.10) — итоговые правила, всё проверено в игре
- **Что держит окно HUD:** привязка `h_pos_align`/`v_pos_align` + флаги `not_movable`/`not_active`/`transparent`/`not_focusable`. Снятие — `profile.hudFree` → `layout[id].free` → `hud.applyEdit({free})`, повтор в конце `buildDialog`
- **За что тащат:** окна с ячейками (бафы, ряды умений, боковая панель) — за ячейки и пустое место; окна без ячеек (карта) — только за тело окна (рамку-пресет). Тело без видимой подложки — **`bld_grip`**: `hud.gripLibrary()` (Skin + Preset `type=window` в `version4.xml`), `hud.gripAtlas()` (8×8, alpha 1/255, в zz_builder.pak); ставится окну без своего пресета. Плюс `hud.addGrip` — окно шире на 16 px справа, `title_frame` на всё окно
- **Таскаются:** бафы, дебафы, мини-карта, панель умений, боковая панель III, ряды Ctrl/Alt, кнопка меню (`hud.FREE_WINDOWS`, список в «Виде интерфейса» `LK_FREE`)
- **Не таскаются (держит код):** цель, бафы цели, портрет с HP/MP — убраны из списка, остаются родными
- **Место НЕ сохраняется:** игра не запоминает перетащенное (после перезахода окна на обычных местах), расстановки в файлах клиента нет (system.cfg — только графика). **Координаты из файла для бафов, карты, панели умений, HP/MP, меню, цели игра не берёт** (проверено: записанные карта x 1772, панель 729,917 — в игре всё на обычных местах)
- **Ряды Ctrl/Alt** без привязки встают по файлу → сборка ставит их стопкой над `ctn_shortcut` основной панели (Ctrl y 858, Alt 815, зазор 3; от места панели в файле, правки рамки панели не в счёт)
- В профиле пользователя остались `layout[…].frame` от отменённого режима «Двигать окна» (бафы, дебафы, карта, панель, HP/MP, цель, меню) — игра их не читает
- Постоянное место — только приёмами через размер окна: бафы «сдвинуть влево», карта «справа вверху» (`arrange.mapTopRight`)

- Главная и тексты инструкции находятся в `src/ui/home.js`.
- Меню свёрнуто до полосы и раскрывается наведением.
- Для запуска использовать `Запуск.cmd` или `npm start` из этой папки.
- `npm run selftest` — обязательная проверка перед сборкой.
- Старый установщик и старые сборочные артефакты не являются рабочей версией.
